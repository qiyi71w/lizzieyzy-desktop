# Function catalog extraction

The committed catalog is extracted from `wimi321/lizzieyzy-next` at `cb53acc55eda42c6c671b5f668cd3b597456bf07`, using its shaded jar (SHA-256 `739d77a2531c766375f617673c37f2de4e9760b7a9fc9dbbebde7ee156a4d6ee`). The extraction yields 360 functions in `FunctionCatalog.entries()` order, six categories, 76 sectioned settings targets, and eight maintained bundles. Search results use Java's ranking, including stable-ID ordering when browsing.

The committed file is then edited in place: Java's two interface-style switches become this product's three 外观模式 entries (`menu.appearanceMode*`), this product's 编辑面板布局… (`menu.editPanelLayout`, under 显示 > 面板, with its title, aliases and description in every bundle) is added, and the eleven 详细工具栏 entries (`legacy.*` and `toolbar.detailed`) are left out, as this product leaves out that toolbar. Six entries whose Java dialogs this product folds into 综合设置 get that page as their `section` (Java extracts `null`): `menu.maxTreeWidth`, `menu.initialMaxScoreLead`, `menu.setReplayInterval`, `menu.minPlayoutsForNextMove` and `menu.setCandidatesDelay` get `"section":"engine"`, and `menu.frameFontSize` gets `"section":"theme"`. The English, Korean and Thai aliases of `menu.kataScolreLead` name the corrected 目数显示 items (see `CORRECTIONS` in `tools/extract_java_strings.py`). The bundle texts that `CORRECTIONS` also fixes carry the corrected text here too: `Config (Shift+X)` for Java's `Shif+X` (English and Thai `Menu.comprehensiveSettings` and `FunctionSearch.aliases.settings.general`), the proxy subtitle `ConfigDialog2.modern.proxy.subtitle` without "Java" in every bundle, and the Thai bundle's double-escaped `\:` and `\uXXXX` (`SetKataRules.lblScoringRule`, five `FunctionSearch.aliases.menu.*`) read as Java's author meant. It holds 351 entries; the bundles keep Java's whole `FunctionSearch.*` vocabulary.

From the repository root, set `JAVA_JAR` to that baseline jar and run with JDK 21:

```sh
javac -cp "$JAVA_JAR" -d /tmp/function-catalog tools/function_catalog/DumpFunctionCatalog.java
java -cp "/tmp/function-catalog:$JAVA_JAR" DumpFunctionCatalog "$JAVA_JAR" crates/lizzie-core/src/function_search/catalog.json
```

The generator reads the real catalog classes and uses `ResourceBundle.Control.getNoFallbackControl(FORMAT_PROPERTIES)`, retaining Java's resource-parent lookup and actual bundle locale. The JSON records the source commit and SHA-256 of the supplied jar. `tools/extract_java_strings.py` consumes these keys when regenerating the UI translations.

The UI translations come from the newer `6a5c8d1524f8bdfd9163162a38dcf64c23402a1b` (`next-2026-11-19.1`), while the entries above stay as extracted. Where that commit changed the text of a key the catalog's entries use, the catalog's bundles carry the newer text too, so that a function is found by the name the UI shows: `BottomToolbar.downloadWeight` (`Update weights`) and `BottomToolbar.gotomove` (`Go to`) in the base and English bundles, and `Menu.diagnosticsAndLogs` and `Menu.stopFullTrace` in the Japanese, Korean and Thai bundles, which the newer commit translates. `BottomToolbar.shareHistoryRemote`, the title of the withdrawn `share.public-history`, keeps its extracted text; the newer commit deleted it.
